# Задачи и сроки

Список ведёт инструмент `tasks`, не память. Для просмотра вызывай `list`, для
завершения — `done`, удаления — `remove`. Список задач показывай владельцу виджетом
(скилл `widgets`): группы по срокам, просроченные первыми. Задача не ставит напоминание: просьба
напомнить исполняется через `remind`.

## Новая задача

В `add` передавай срок только календарной датой `YYYY-MM-DD`; без срока пропускай
`due` или передавай `null`. Это день, не момент времени. Не превращай дату в UTC
и не выдумывай час исполнения.

Смысл «завтра», «в пятницу», «через неделю» определяй по просьбе и текущим дате
и часовому поясу владельца, которые приходят в начале хода. Например, «завтра»
при дате владельца 2026-09-23 становится `due:"2026-09-24"`. Если дата в просьбе
неоднозначна — уточни. Если указан точный час, уточни, нужен ли `remind`, и сохрани
важную для задачи подробность в её тексте. В ответе повтори фактически сохранённую дату.

## Исправление срока и старые задачи

1. Вызови `list` (для выполненной задачи — `includeDone:true`). Возьми `id`,
   исходный `due` и `createdAt`. Никогда не правь `tasks.json` напрямую.
2. Старые строки вроде «завтра» считай от даты создания задачи, не от сегодняшней
   даты. `createdAt` — UTC-момент: сначала установи календарную дату в часовом поясе
   владельца на момент создания. Если историческая зона неизвестна, не считай текущую
   доказательством: уточни у владельца. Для «в пятницу» и похожих форм восстанови
   контекст просьбы из памяти либо уточни значение; одной строки бывает недостаточно.
3. В обзоре дня (скилл `brief`) можно показать подтверждённую абсолютную дату без изменения файла.
   Если смысл неизвестен, покажи исходный срок и вопрос для уточнения. Не перемещай
   такую задачу в категорию «без срока» и не объявляй её непросроченной.
4. Когда владелец просит исправить срок и дата установлена, вызови
   `update` с `id`, новой датой `due` и точным исходным `expectedDue` из `list`.
   Например: `{action:"update",id:117,due:"2026-09-24",expectedDue:"завтра"}`.
   Для снятия срока передай `due:null`; если срока прежде не было — `expectedDue:null`.
5. Если тул сообщает, что срок изменился, перечитай `list` и заново сопоставь
   намерение владельца с актуальной записью. Не повторяй старое исправление вслепую.

Автоматической миграции нет: старые строки остаются данными владельца, пока он
не попросит их исправить. При группировке сравнивай абсолютные календарные даты
с сегодняшней датой владельца; прошедшие сроки допустимы.
