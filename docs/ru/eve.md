# Сборка и публикация eve

Исходники eve лежат в `eve/`: копия [vercel/eve](https://github.com/vercel/eve)
на коммите `eb5949a622801b35a2a6f78bb58d9eef27273cac` (eve 0.51.1).
В ней пакет eve, зависимость catalog и входы сборки. Тестов upstream,
документации пакета и кода, который Ива не загружает, в копии нет (ADR-0027);
убранные входы и команды перечислены в таблице ниже. Документация eve — на
https://eve.dev/docs. Правки Ивы — обычные коммиты в этом каталоге; их держат
тесты границы Ивы. Переход на новый коммит upstream — отдельное решение по ADR-0023.

| Убрано                                                                                                                                                                                                       | Что это было                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `eve/react`, `eve/vue`, `eve/svelte`                                                                                                                                                                         | клиентские хуки для веб-интерфейсов                                                       |
| `eve/next`, `eve/nuxt`, `eve/sveltekit`                                                                                                                                                                      | адаптеры фреймворков-хостов                                                               |
| `eve/self-modification`, `eve/self-modification/agent`, `eve/self-modification/sandbox`                                                                                                                      | встроенный eve Extension self-modification                                                |
| `eve/channels/slack`, `eve/channels/teams`, `eve/channels/discord`, `eve/channels/linear`, `eve/channels/twilio`, `eve/channels/chat-sdk`, `eve/channels/photon`, `eve/channels/linq`, `eve/channels/github` | каналы, кроме Telegram, канала eve и MCP                                                  |
| `eve/setup`, `eve/setup/scaffold`                                                                                                                                                                            | мастера убранных команд                                                                   |
| `eve acp`                                                                                                                                                                                                    | сервер ACP через stdio                                                                    |
| `eve init`, `eve set`, `eve integration`, `eve add`, `eve registry`, `eve link`, `eve deploy`                                                                                                                | создание проекта, настройки модели, интеграции, позиции каталога eve и выкладка на Vercel |

В копии остаются `eve build`, `eve start`, `eve dev` с терминальным интерфейсом
(и `/add` внутри него), `eve extension`, `eve invoke`, `eve logs`, `eve traces`,
`eve info`, `eve channels`, `eve eval` и остальные входы пакета. Плагин или
инструмент в `data/custom`, который импортирует убранный вход, на этой копии не
собирается: `iva update` выключает такой плагин и называет его владельцу,
`iva plugin add`, `update` и `enable` ему отказывают (ADR-0027, «Цена»).

Правьте `eve/packages/eve/src/`, прогоняйте тесты границы Ивы, которые называют
изменённое поведение, затем коммитьте исходники. Мейнтейнер использует Node ≥24
и pnpm 11.25.0. Для нового архива задайте свежий номер `0.51.1-iva.N` в
`scripts/build-eve.sh` и `scripts/eve-release.sh`. Пользователь получает готовый
пакет eve и собирает только агента Ивы.

Из чистого дерева:

```sh
bash scripts/eve-release.sh
```

Команда вызывает `scripts/build-eve.sh`, сохраняет архив в игнорируемый
`.eve-out/release/`, считает SHA-512 SRI и записывает URL, версию и integrity в
`package.json` и `package-lock.json`, а версию и хеши исходников и пакета — в
отслеживаемый `eve.lock.json` вне `eve/`. Повторный запуск использует тот же архив,
сверив хеши исходников и пакета. Новым исходникам нужен новый номер N.
Для сравнения сборок: `bash scripts/build-eve.sh <пустой-каталог>`.

Закоммитьте три файла зависимости локально, затем выполните:

```sh
bash scripts/eve-release.sh --publish
```

Команда проверяет чистое закоммиченное дерево и подготовленный архив, создаёт
и отправляет только метку `eve-0.51.1-iva.N`, создаёт выпуск GitHub и загружает
архив, скачивает его по итоговому URL со сверкой SHA-512 SRI, затем выполняет
`npm ci` во временном чистом дереве с пустым кэшем. Первый сбой останавливает
команду. Финальное сообщение разрешает лиду отправить `beta`; отправка остаётся
отдельным действием после обязательной приёмки. Путь к архиву можно передать
последним аргументом в обоих режимах.

Опубликованные метки `eve-*`, имена вложений и байты архивов постоянны.
Исправление получает новый N: старые версии Ивы используют прежние URL.
Архивы хранятся вне git.

В `node_modules/eve/BUILD.json` лежат коммит upstream, версии пакета и
инструментов, `sourceTreeHash` и `packedTreeHash`. Тест `scripts/eve-copy.test.ts`
сверяет исходники и установленный пакет с `eve.lock.json`, затем метаданные
BUILD и lockfile. Из прав файла хешируется только признак исполнимости:
umask сохраняет хеш. Сборочный `.vendor-stamp.json` исключён из хеша пакета;
его отпечаток использует относительные пути, поэтому байты архива совпадают
при сборке в разных каталогах.

## Проверка правки eve

Своего набора тестов у копии нет. Правку eve проверяют со стороны Ивы:

- Изменение поведения держит тест границы Ивы, который называет изменённое
  поведение eve (`scripts/eve-*.test.ts`, ADR-0023), затем гейт уровня задачи.
- Правку, которая поведение Ивы менять не должна (удаление, правка сборки),
  сравнивают со сборкой Ивы до правки. Сохраните `.output` после `npm run build`
  на старом архиве, поставьте новый, соберите снова и выполните
  `node scripts/eve-bundle-equal.ts <старый>/.output/server .output/server`.
  Код 0 и строка `EQUAL` значат: модули eve (маркеры `//#region` и вложенный
  бандл workflow в base64) — тот же набор, и каждый совпадает с прежним с
  точностью до имён привязок. Литералы, операторы, имена свойств и порядок
  инструкций те же, имена сопоставлены взаимно-однозначно, импорты и экспорты
  чанка совпадают как множества, отличаться может только номер архива eve.
  Любое другое отличие откатывает удаление.
- `npm run build`, `node bin/iva.mjs version`,
  `node node_modules/eve/bin/eve.js --help` и
  `node node_modules/eve/bin/eve.js start --help` завершаются с кодом 0, тесты
  границы eve (`scripts/eve-copy.test.ts`, `scripts/eve-release.test.ts`,
  `scripts/eve-archive-update.test.ts`, `scripts/lib/plugin-build-eve.test.ts`)
  зелёные с `EVE_LOCAL_ARCHIVE`, равным пути архива при установке.
- `scripts/eve-copy.test.ts` закрепляет, чего в копии больше нет, и команды
  CLI, которые зовёт Ива.

eve собирается одной программой rolldown. Удаление исходного файла
переставляет импорты и переименовывает локальные переменные или совпавшие
имена верхнего уровня в оставшихся файлах, поэтому сверка идёт с точностью до
имён, а не побайтно. Три части остаются, потому что без них меняется сама
программа: терминальный интерфейс `eve dev` с мастерами setup и
`compiled/shadcn-registry` (Ива зовёт `eve dev`); evals, без которых из общего
`_virtual/_rolldown/runtime.js` уходят помощники CommonJS; вендорные
зависимости убранных каналов, без которых меняются имена общих чанков
`compiled/_chunks/node`.
