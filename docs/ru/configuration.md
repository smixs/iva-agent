# Конфигурация

Iva настраивается одним файлом: `.env` в директории установки. Мастер установки заполняет его за вас — любой шаг можно переиграть командой `iva config` ([cli.md](../cli.md)). Шаблон — `.env.example` в корне репозитория. На этой странице описана каждая переменная.

**Любое изменение требует перезапуска.** Iva читает `.env` один раз при старте. После правки:

```bash
iva restart
```

Пересборка не нужна. Сменить модель, ключ или провайдера — это правка → перезапуск.

**Одно исключение — язык ответов.** Кнопка **🌐 Язык** в `/menu` пишет `data/settings.json`, который оба процесса перечитывают на лету — смена срабатывает сразу, без перезапуска. См. [menu.md](../menu.md).

## Провайдер модели

Шесть провайдеров. Выберите один через `MODEL_PROVIDER` и заполните только его блок. `ollama`/`opencode`/`openrouter` — API-ключ (OpenAI-совместимы); `codex` — личная подписка OpenAI (ChatGPT) по OAuth, без ключа; `claude` — подписка Claude Pro/Max через CLI `claude`, залогиненный на том же сервере, тоже без ключа; `custom` — любой OpenAI-совместимый эндпоинт, адрес которого вы задаёте сами. Цены и полные списки моделей: [providers.md](../providers.md).

`*_VISION_MODEL` — запасной путь, а не основной. На первой входящей картинке Ива одним маленьким запросом спрашивает саму модель чата, принимает ли она картинки. Принимает — картинка идёт прямо ей, пикселями, без пересказа, и vision-модель не зовётся вовсе. Отвечает отказом — картинка уходит в `*_VISION_MODEL`, и модель получает её описание, как раньше. Ответ помнится до перезапуска процесса: после рестарта и после смены модели вопрос задаётся заново. Следствие смены на модель без зрения: у картинок, присланных раньше, описания не сохранено — при нужде перешлите фото заново.

Ровно эти шесть имён, буква в букву. Любое другое значение, включая опечатку и другой регистр, останавливает агента на старте и печатает список принятых имён, вместо того чтобы запустить Ollama под именем, которого никто не задавал. То же самое скажут `iva doctor` и экран «📊 Статус» в `/menu` ([troubleshooting.md](../troubleshooting.md)). Если строки `MODEL_PROVIDER` нет вовсе, это по-прежнему `ollama`.

Для `custom` ничего не угадывается: `CUSTOM_BASE_URL` и `CUSTOM_MODEL` — две строки, без которых провайдер не работает, и пустая из них это отказ на старте с именем переменной, а не тихий дефолт. `THINKING_EFFORT` намеренно не действует на `custom`: OpenAI-совместимость ничего не обещает про `reasoning_effort`, и слать его вслепую чужому эндпоинту — риск HTTP 400 на каждом ходу. Полный сценарий: [providers.md](../providers.md#your-own-openai-compatible-endpoint-custom). Пример облачного эндпоинта с оплатой в рублях и доступом из России без VPN: `CUSTOM_BASE_URL=https://api.neuraldeep.ru/v1`, `CUSTOM_MODEL=qwen3.6-35b-a3b` (инструменты и картинки в одной модели), `CUSTOM_CONTEXT_WINDOW=262144`, ключ из [hub.neuraldeep.ru](https://hub.neuraldeep.ru/app).

Для `codex` ключа в `.env` нет: выполните `iva login` (по ссылке+коду, годится для headless-VPS) или `iva login --browser`. OAuth-токен лежит в `data/codex-auth.json` (chmod 600, в gitignore) и автоматически обновляется до истечения. Полный сценарий: [providers.md](../providers.md#openai-by-chatgpt-subscription-codex).

**Не завышайте контекстное окно.** Сжатие истории срабатывает на 70% этого числа. Поставите больше реального окна модели — компактор включится слишком поздно: запрос переполнится раньше, чем история будет подрезана. Меняете модель — вписывайте её настоящее окно, а не круглое число побольше.

Список разрешённых работает по принципу **fail-closed: пустой список — Iva не отвечает никому.** Мастер сам подхватывает ваш ID, как только вы напишете боту; или спросите у [@userinfobot](https://t.me/userinfobot). Почему fail-closed важен: [security.md](./security.md).

В 10:00 по `ASSISTANT_TIMEZONE` Iva без обращения к модели проверяет Git upstream. Пока новой стабильной версии `MAJOR.MINOR.PATCH` нет, сообщений не будет; каждую новую версию Iva предлагает только один раз. Если `TELEGRAM_DIGEST_CHAT_ID` пуст, используется первый доверенный ID.

## Уведомления

То, что Iva говорит сама, живёт в `data/settings.json`, а не в `.env` - эти ключи пишет экран **🔔 Уведомления** в `/menu`, а тумблер отчётов читается в конце каждого ночного прогона, тумблер дайджеста — когда срабатывает его расписание - поэтому тап срабатывает без перезапуска.

| Ключ                     | По умолчанию | Заметки                                                                                              |
| ------------------------ | ------------ | ---------------------------------------------------------------------------------------------------- |
| `memoryReports.enabled`  | `false`      | Ночной отчёт памяти (daily 04:00 и weekly пн 04:15) в Telegram. Выключено - vault всё равно пишется. |
| `digestSchedule.enabled` | `false`      | Утренний дайджест в 08:00. Команда `/digest` работает руками в любом случае.                         |

Алерты - о проблемах (память не бэкапится, ночной проход не прошёл) и о новых версиях - приходят всегда: их нельзя выключить, но каждый говорит, что делать, и повторяется не чаще раза в неделю на проблему - [ADR-0007](../adr/0007-notices-are-opt-in.md).
