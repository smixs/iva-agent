# Раз в день Ива отвечает на перекличку: число живых установок без идентификатора

Решение владельца 26.11.2026: «как встроить в наш проект минимальную … чтобы собирать статистику, сколько
юзеров, какие модели используют - анонимно и легально … это только для понимания паттернов и улучшения. а то я даже
не знаю, сколько у меня юзеров ивы». На вопросы: по умолчанию — «включён без сообщения, отключить можно глубоко в
настройках»; цифры — «только мне»; хеш адреса в счёте установок плагинов — убрать. Уточняет ADR-0029.

**Причина.** Сколько Ив работает, не знает никто. GitHub считает только полные клоны, а не ежедневный `git fetch`
проверки обновлений («full clones (not fetches)», документация GitHub), поэтому живые установки по трафику
репозитория не видны. Скачивания `install.txt` показывают попытки новых установок вместе с ботами. Без числа живых
установок, их версий и провайдеров нельзя решить, на каких провайдерах гонять проверку перед выпуском, дошёл ли
выпуск до людей и растёт ли проект.

**Решение.**

1. После ежедневной проверки обновлений (тот же ежедневный запуск, `scripts/check-update.ts`) Ива отправляет один POST на
   `https://iva-agent.com/api/roll-call` с телом из семи полей, например
   `{"gap":1,"version":"0.5.16","branch":"main","os":"linux","arch":"x64","provider":"codex","model":"gpt-5.5"}`.
   Весь запрос записан в одном файле, `scripts/lib/roll-call.ts`.
2. Идентификатора нет. `gap` — сколько дней прошло с прошлой переклички, которую сайт принял: 0 у первой, не больше 31. Этого хватает, чтобы сайт посчитал разные установки за любое окно до месяца, не отличая их друг от друга:
   установка считается в первой перекличке окна, а у неё `gap` дотягивается до начала окна. Приём взят у OpenClaw
   (`src/infra/telemetry-installation-count.ts`). Ива — служба и работает круглые сутки, поэтому перекличка раз в
   день и есть число живых установок.
3. Каждое поле берётся из закрытого списка, версия — по строгой форме: версия только вида `X.Y.Z`, ветка
   обновлений `main`/`beta`, ОС `linux`/`darwin`, архитектура `x64`/`arm64`, провайдер из списка провайдеров Ивы, модель — только
   имя, которое для этого провайдера называет список моделей Ивы (`scripts/lib/model-catalog.ts`); всё прочее уходит как
   `other`. Своё имя модели — дообученная модель, файл, развёртывание на своём сервере — может сказать, чья это
   установка, поэтому оно не уходит; много `other` у одного провайдера — повод дополнить список моделей. У провайдера
   `custom` модель всегда `custom`, его адрес не читается. Ни одно значение `.env` не может унести с машины что-то
   иное: это сторожит тест на свойство.
4. Одна перекличка в сутки по UTC: день переклички, которую сайт принял, пишется в `data/roll-call.json`. Перекличка
   идёт под тем же замком, что проверка обновлений и `iva update`, поэтому два запуска сразу дают одну. Сайт не ответил —
   день не пишется, завтра уйдёт перекличка с большим `gap`. Отправка ждёт не дольше 2,5 секунды, ничего не бросает и
   не меняет код выхода проверки обновлений. В журнал службы уходит строка `Roll call: <тело>`.
5. Сайт хранит только счётчики «день, поле, значение → сколько»: отдельно по каждому полю, без строк со всеми полями
   сразу, чтобы редкая связка не выдала установку. Адрес отправителя не пишется и не хешируется. Тело, в котором
   есть чужое поле или значение не своей формы, отклоняется. Сайт проверяет формы, а не списки: Ива новее сайта может
   назвать провайдера, которого сайт ещё не знает. Модель без единой буквы или с двумя двоеточиями похожа на адрес и
   отклоняется. Семь счётчиков переклички пишутся одной транзакцией. Цифры видит только владелец проекта: наружу они не показываются.
6. Выключатель — `IVA_STATS=off` в `.env`; `DO_NOT_TRACK=1` делает то же. Сообщения владельцу в чат нет: решение
   владельца. Выключатель и запрос целиком описаны в `docs/configuration.md` и `SECURITY.md`. `IVA_STATS=off`
   выключает и счёт установок плагинов; `IVA_PLUGIN_STATS=off` по-прежнему выключает только его.
7. Уточнение ADR-0029, п. 5: сайт больше не хранит суточный хеш адреса для счёта установок плагинов, таблица `seen`
   удаляется. Хеш адреса с солью, пока соль жива, остаётся персональными данными (преамбула 26 GDPR), а с 01.07.2025
   ч. 5 ст. 18 152-ФЗ запрещает при сборе данных россиян базу за рубежом. Повторы установки плагина редки: её
   делает человек.

**Отвергнуто.** Случайный идентификатор установки (Home Assistant, Hermes, Next.js): он нужен для кривых удержания,
а связка «идентификатор и адрес в одном запросе» по Суду ЕС скорее персональные данные (IAB Europe C-604/22) и
попадает под 152-ФЗ. Хеш адреса с суточной солью для отсева повторов: те же причины, повторы гасит сама Ива по своей
отметке дня. Статистика внутри проверки обновлений, как у WordPress: проверка обновлений идёт к GitHub, а смешение
нужного с необязательным — то, на что жалуются пользователи WordPress с 2011 года. Включение только по согласию
(Home Assistant, Go, Hermes): цифры показали бы только согласившихся, а вопрос был «сколько у меня юзеров». Открытый
показ цифр: владелец решил «только мне». Отправка страны, языка, числа сообщений, списка плагинов: ни одно
решение от них не зависит.

**Цена.** Это вторая исходящая отправка Ивы ради статистики и первая без действия владельца. Она включена по
умолчанию и без сообщения в чат: часть людей узнает о ней только из документации, а молчаливое включение — одна из
причин, по которым сбор статистики в других проектах вызывал гнев (.NET, GitLab 2019). Остаётся риск директивы ePrivacy
ст. 5(3) для владельцев в ЕС, которые держат Иву на своём Mac. Без отсева повторов на сайте любой может накрутить
счёт запросами; цифры видит только владелец проекта, поэтому вред ограничен его выводами. Перекличка занижает:
не видны выключившие её и серверы, с которых сайт недоступен.
