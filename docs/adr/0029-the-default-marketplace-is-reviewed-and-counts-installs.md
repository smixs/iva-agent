# Маркетплейс по умолчанию проверяется, установка из него считается по имени

Решение владельца 22.11.2026: приём — «PR с проверкой», популярность — «Счётчик установок», и «надо чтобы
юзеры тоже по ранбуку делали плагины и мы могли видеть их репозитории». Уточняет ADR-0009 в двух местах:
список `smixs/iva-plugins` перестаёт быть списком, который никто не читал, и Ива впервые сообщает наружу
о своём действии. Остальное в ADR-0009 остаётся как было.

**Причина.** Плагины сообщества появились, а найти их можно было только в переписке. Список по умолчанию
ставится по имени у каждого владельца, поэтому запись в нём читается как рекомендация, хотя до сих пор её
никто не проверял. Страница плагинов на сайте без порядка «что ставят чаще» показывает шесть карточек
одинаково, и автору не видно, нужен ли его плагин кому-то.

**Решение.**

1. Проверяется один список, `smixs/iva-plugins`. Запись попадает в него pull request'ом, после того как
   сопровождающий прочитал код на названном коммите: что запускается на машине, какие ключи читаются, куда
   плагин ходит в сеть. Плагин из чужого репозитория закреплён `sha` без `ref`; новая версия — новый pull
   request, читается разница двух коммитов. Свои маркетплейсы владельца остаются без центра и проверки.
2. Для кода Ивы ничего не меняется: файл списка по-прежнему недоверенный ввод, разбор не верит ни одному
   полю, плагин с кодом ждёт тапа владельца (ADR-0009). Проверка списка не заменяет ни одну из этих границ.
3. Карточка плагина для сайта (категория, автор, репозиторий, что запускает) лежит в `cards.json` рядом со
   списком, а не в `marketplace.json`: установленная Ива сообщает о каждом незнакомом поле списка вслух.
4. Автор держит плагин в своём публичном репозитории с темой `iva-plugin`; скилл `make-plugin` доводит до
   pull request'а со ссылкой на этот репозиторий.
5. После успешной установки Ива отправляет один POST на `https://iva-agent.com/api/plugins/installs` с телом
   `{"name":"<имя>"}`. Отправка идёт в двух случаях: `iva plugin add <имя>` взял плагин из списка по умолчанию;
   установка по тапу поставила плагин, имя которого есть в этом списке. В запросе нет идентификатора
   установки, версии, модели и ключей. Сайт видит адрес сервера, как видит его любой сайт, и сутки хранит его
   хеш с суточной солью, чтобы одна машина не считалась дважды за день; сам адрес не хранится.
6. Выключатель — `IVA_PLUGIN_STATS=off` в `.env`; `DO_NOT_TRACK=1` в окружении делает то же. Отправка идёт
   последним действием команды, ждёт не дольше 2,5 секунды и на установку не влияет: отказ сети молчит.
   Каждая отправка печатает строку, что ушло и как выключить.

**Отвергнуто.** Поля карточки в `marketplace.json`: каждая уже установленная Ива печатала бы предупреждение на
каждое поле. Идентификатор установки ради точного счёта: он превращает счётчик в учёт владельцев. Счёт по
клонам репозитория на GitHub: чужие репозитории его не отдают, а свой считает и роботов. Счёт обновлений и
`iva plugin sync`: это та же установка. Отправка для своих маркетплейсов и прямых источников: имя такого
плагина владелец не публиковал.

**Цена.** Это первая исходящая отправка Ивы, сделанная ради статистики; до неё Ива ходила наружу только за
тем, о чём просил владелец, и за обновлением. Счётчик занижает: не считаются выключившие его, серверы, с
которых сайт недоступен, и установки по адресу репозитория. Проверка списка — работа сопровождающего на каждый
pull request; запись в списке означает «этот коммит прочитан», а не «плагин безопасен на любой машине».
