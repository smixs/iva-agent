# Проверка Ивы

Три яруса дополняют друг друга: свойства перебирают входы и последовательности,
герметичные e2e проверяют настоящие процессы и HTTP, живая проверка мейнтейнера
подтверждает ответ и доставку на действующей установке c1.

`npm run smoke` запускает свойства и герметичные e2e с двумя параллельными файлами.
`npm run smoke:full` увеличивает число прогонов каждого свойства с 30 до 500.
Для повтора используйте `SMOKE_SEED=12345 npm run smoke`: seed печатается в выводе.
`SMOKE_RUNS` задаёт своё число прогонов свойств. TODO с готовым телом выполняются и показывают известные дефекты; после починки
пометка снимается. Их перечень проверяет сторож таблицы.

Каждый e2e получает временные данные, свои порты и закрытое окружение. Telegram
и провайдер отвечают локальными HTTP-серверами. При успехе временные файлы
убираются; при провале путь к журналам и состоянию выводится в терминал.
`TMPDIR` позволяет выбрать каталог на диске для временных файлов.

| id                  | ярус     | что проверяет                                                                                                                                                                            | ждёт починки |
| ------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| S-chat-reply        | e2e      | Сообщение даёт ровно один ответ; дубли и переставленные update сохраняют один ход.                                                                                                       | —            |
| S-chat-notice-reply | e2e      | Reply на настоящий текст сторожа передаёт цитату как своё сообщение; первый промежуточный текст приходит за ≤60 с до завершения инструментов, один раз; чужая цитата остаётся untrusted. | —            |
| S-chat-overload     | e2e      | Повтор после 429, понятный отказ при исчерпании и ответ на следующее сообщение.                                                                                                          | —            |
| S-chat-reset        | e2e      | Одно подтверждение /new, новая сессия и ExactCut после обрыва Bridge.                                                                                                                    | —            |
| S-rem-ontime        | e2e      | Создание через инструмент, настоящий тик и ход модели; один текст в исходную тему, задержка печатается.                                                                                  | —            |
| S-rem-reset         | e2e      | Доставка при /new и один Alert после SIGKILL без второго текста.                                                                                                                         | —            |
| S-update-cycle      | e2e      | Старый CLI, handoff, обрыв и повтор до settled; откат сохраняет data/.                                                                                                                   | —            |
| S-update-cycle-pin  | e2e      | Успех UpdateJob публикуется после закрепления версии в active.json.                                                                                                                      | —            |
| S-wire-out          | e2e      | Плоские схемы, подпись при отказе виджета в ту же тему, секрет остаётся внутри.                                                                                                          | —            |
| P-formats           | свойство | Форматы выпусков 0.5.0–0.5.12 читаются и пишутся без потерь; будущий формат сохраняет байты при отказе.                                                                                  | —            |
| P-queue             | свойство | Команды QueueDrain: входы сохранены, порядок чата и итог при дублях совпадают.                                                                                                           | —            |
| P-reminder          | свойство | Одноразовые строки ReminderLifecycle: один захват и факт, падение, /stop, устаревший факт и один Alert.                                                                                  | —            |

Готовый текст напоминания отправляет секундный Schedule без хода модели (ADR-0013).
S-rem-ontime проверяет срок ≤15 секунд, исходную тему и отсутствие хода модели;
задание сохраняет прежний ход. P-reminder проверяет одноразовые строки;
S-rem-reset закрепляет доставку текста при /new. F1 и R1 выполняются обязательно,
без TODO.

Живой ярус запускает мейнтейнер на c1 по своему ранбуку. Он использует настоящие
Telegram и модель; его сценарии и доступы хранятся отдельно от герметичного набора.
