# Iva

Глоссарий проекта. Одно понятие — одно слово. Слова из колонки _Avoid_ не
использовать ни в коде, ни в доках, ни в обсуждениях. Решения записаны в
`docs/adr/`, метод — в `docs/philosophy.md`.

## Language

### Память

**Vault**:
Личное хранилище памяти пользователя — markdown-файлы в отдельном приватном
git-репозитории.
_Avoid_: база, хранилище памяти, knowledge base

**Card (карточка)**:
Типизированная единица памяти в `vault/cards/` с frontmatter по `schema.json`.
_Avoid_: заметка, запись, документ

**Compiled Truth**:
Актуальное значение карточки: frontmatter плюс верхнее описание. То, что
считается правдой сейчас, в отличие от истории изменений.
_Avoid_: current value, действующая правда

**History**:
Append-only секция `## History` карточки. Пишется только кодом; модель не может
вложить в неё выдуманный архив. Строка Compiled Truth, которую заменила новая,
уходит сюда с датой; строку, написанную человеком, ночь не меняет, а дописывает
новое рядом.
_Avoid_: лог карточки, архив

**CORE**:
Always-on память: `vault/CORE.md`, не длиннее 3600 знаков, инжектится в каждый
ход.
_Avoid_: системный промпт (это не он), ядро

**PERSONA**:
Стиль общения агента: `vault/PERSONA.md`, не длиннее 800 знаков, инжектится в
каждый ход.
_Avoid_: характер, персонаж

**MOC**:
Индекс тем vault (`vault/MOC.md`); код обновляет его в момент создания карточки.
_Avoid_: оглавление, каталог, регенерация индекса

**Rollup**:
Ночная сборка памяти: сырой день превращается в карточки и саммари по цепочке
daily → weekly → monthly → yearly. Круг ведёт код: четыре Step, на каждом модель
получает только нужное и отвечает один раз; файлы пишет код (ADR-0016).
_Avoid_: consolidation, консолидация, DAG, диаризация, свободный цикл
(диаризация — название способности модели в philosophy.md, не процесса)

**Step (шаг ночи)**:
Один из четырёх запросов Rollup к модели с входом, который собрал код, и одним
ответом: день → карточки → связи → CORE. Модель может один раз попросить ещё
карточки; открытого цикла инструментов нет.
_Avoid_: turn для шага (Turn — ход), фаза, итерация, шаг агента

**Ceiling (предел ночи)**:
Верхняя граница расхода одной ночи: запросы и входные токены. Достигнут —
ночь останавливается, остаток дней ждёт следующей ночи, отчёт это называет.
_Avoid_: бюджет, лимит (лимит — у провайдера), quota, потолок

**Attempt (попытка дня)**:
Один запуск Rollup над одним днём. У дня их ограниченное число за сутки; после
него день ждёт человека (`iva jobs skip`), а не новой попытки на каждом старте.
_Avoid_: retry, ретрай, повтор

**Trial run (пробный прогон)**:
Rollup над настоящими днями с записью в копию vault; настоящий vault ведёт
действующая ночь. Так новая ночь сравнивается со старой до включения.
_Avoid_: shadow mode, тень, dry-run (dry-run — печать плана у команды)

**Forget (забыть)**:
Удаление по явной команде владельца всех следов сущности или темы: карточки,
строки CORE, упоминания в днях и саммари, история git. Сначала перечень, потом
«да» владельца, потом удаление.
_Avoid_: очистка, purge, стирание, decay

**Month (месяц памяти)**:
Календарный месяц, с 1-го по последнее число; monthly-саммари берёт недели по
краям частями. Неделя остаётся как есть.
_Avoid_: четыре недели, 28 дней

**Brain**:
Детерминированный ночной уход за vault (бывший «memory doctor»): бэкап, коммит,
алерты. Без модели и без внешних скриптов (ADR-0016).
_Avoid_: memory doctor, доктор памяти, autograph (как имя процесса Ивы)

### Процессы

**Harness**:
Тонкая программа-обвязка вокруг модели: eve плюс минимальный слой интеграции.
Определение и границы — в `docs/philosophy.md`.
_Avoid_: фреймворк, платформа

**Bridge (мост)**:
Отдельный процесс long-polling Telegram → localhost POST в eve. Живёт в
`scripts/poller/`, работает даже когда агент занят или завис.
_Avoid_: poller, поллер, transport

**Turn (ход)**:
Одна обработка входящего сообщения агентом, от приёма до ответа.
_Avoid_: run (это eve workflow run — внутренняя сущность), job (Job — запуск расписания, не ход)

**Job (запуск расписания)**:
Один запуск одного расписания с фактом результата в `data/jobs.json`.
НЕ ход агента (Turn) — ход, который будит запуск, остаётся Turn.
_Avoid_: job для хода агента, «джоба», запуск расписания как Turn

**Doctor**:
`iva doctor` — диагностика и починка инсталляции. Только про установку, не про
память.
_Avoid_: использовать слово для ухода за памятью (это Brain)

**Skill**:
Markdown-процедура агента (`agent/skills/` — ядровые, custom layer —
пользовательские). Кодирует «как делать», конкретику подставляет вызов.
Содержимое плагина или ядра, а не единица поставки.
_Avoid_: расширение

**Plugin (плагин)**:
Папка формата Agent Plugins: `plugin.json`, `skills/`, `mcp.json` и наш код под
`sh.iva/` (eve Extension, сервисы). Единица расширения Ивы. Ставится командой
`iva plugin add` из Marketplace, git-источника или локальной папки в
`data/custom/plugins/` (ADR-0008, ADR-0009).
_Avoid_: расширение (как термин), addon, модуль

**Marketplace (маркетплейс)**:
JSON-список плагинов в git-репо (`.agents/plugins/marketplace.json`, конвенция
Codex): имя → источник. У Ивы один по умолчанию, владелец добавляет свои. Не
реестр: без центра и модерации.
_Avoid_: реестр, registry, стор, каталог

**MCP proxy (прокси)**:
Сервис Ивы, который держит stdio MCP-сервер плагина и отдаёт его агенту по
streamable-http на loopback с bearer. Один сервис на один сервер.
_Avoid_: мост, bridge (это Telegram-поллер), gateway

**Plugin service (сервис плагина)**:
Долгоживущий процесс плагина, объявленный в `sh.iva/services/<svc>/service.json`:
Ива поднимает его юнитом `iva-plugin-<name>-<svc>.service` и сообщает выданный порт
через `IVA_SERVICE_PORT`. Своего протокола Ива ему не задаёт — этим он и отличается
от MCP proxy.
_Avoid_: демон, воркер, sidecar

**Trace (трейс)**:
Журнал событий хода в `data/trace/`: eve-события через хук плюс швы Ивы
(Bridge, Inbound pipeline, Gate, Outbox). Пишет ядро; читают вьюер плагина
`trace` и `iva trace`. Один ход = цепочка событий с общим `turn`.
_Avoid_: лог (это журнал сервиса), телеметрия, OTel-трасса (внутренность eve)

**Schedule**:
Внутрипроцессный cron eve (`agent/schedules/`). Диспетчер напоминаний — такой же
минутный Schedule. Systemd-таймеры и `systemd-run` — отдельные механизмы, зовутся
своими именами.
_Avoid_: cron (без уточнения какой)

### Доставка и установка

**Authored tree**:
Поставляемое ядро агента — дерево `agent/`, которое eve открывает по
file discovery. Обновляется релизами.
_Avoid_: core (перегружено), исходники агента

**Custom layer**:
Пользовательский оверлей `data/custom/agent/**`, переживающий обновления.
Сюда же ставятся плагины.
_Avoid_: authored layer, кастомизация (как термин)

**Owner rules (правила владельца)**:
Markdown-файлы `data/custom/agent/instructions/*.md`, которые читаются с диска каждый ход
рядом с встроенной персоной; в чате их пишет модель через `write_file` после подтверждения
владельца. Не CORE (там факты и цели), не PERSONA (там стиль из квиза), не код (сборка не
нужна).
_Avoid_: кастомная персона, замена инструкции, override

**Release**:
Опубликованная версия проекта: semver-тег и запись в CHANGELOG. Только
патч-инкременты; минор и мажор объявляет владелец.
_Avoid_: версия (без уточнения)

**Version (каталог версии)**:
Неизменяемый каталог установки `~/iva/versions/<ver>-<sha12>/` в апдейтере v2.
Активную версию выбирает симлинк `current`; откат — переброс симлинка.
_Avoid_: билд, инсталляция

**Update branch**:
Git-ветка, с которой `iva update` берёт код.
_Avoid_: канал обновления, update channel (channel зарезервирован за eve)

**Button (кнопка)**:
Элемент rich message (`<tg-button>`), стоящий в строке текста рядом с пояснением, что он
делает; несёт `callback_data`. Единственный способ дать пользователю выбор тапом: Bridge
рисует их для экранов меню и мастеров, модель — в ответе по скиллу `rich-replies`.
Тап по кнопке модели Bridge превращает в обычное сообщение пользователя с текстом из
`callback_data`. (ADR-0015)
_Avoid_: inline-клавиатура, reply_markup, клавиатура

**Screen (экран)**:
Одно сообщение меню или мастера, которое Bridge правит на месте: markdown с заголовком,
пояснениями и кнопками. Экран возвращает одну строку текста, а не «текст + ряды».
_Avoid_: клавиатура, форма, страница

### Уведомления

**Notice (уведомление)**:
Всё, что Iva шлёт сама, без хода пользователя. Видов ровно два: Report и Alert.
_Avoid_: notification, пуш, рассылка

**Reminder (напоминание)**:
Разовая просьба пользователя, исполняемая в срок. Живёт строкой в таблице напоминаний
`data/`; минутный Schedule-диспетчер забирает созревшие строки одним атомарным переходом
`pending → fired`, а ребёнок в срок делает одно дело: текст строки идёт промптом в свежую
сессию, агент выполняет его инструментами, и код отправляет финальный текст хода в чат и
тему, где напоминание попросили. Хода не было или он промолчал - код шлёт текст строки как
есть. Не Report и не Alert: это прямое исполнение просьбы, и тумблеры Notice его не
выключают.
_Avoid_: notification, напоминалка, alarm, режим доставки

**Routine (рутина)**:
Повторяющееся напоминание: строка той же таблицы в `data/` с расписанием и зоной владельца,
которую диспетчер забирает по сроку на каждом срабатывании. Факт последнего срабатывания
(`firedAt`, `delivered`, `error`) лежит в той же строке, в срок происходит то же самое, что
у разового. Ставится тем же тулом `remind` с `action: "add"`.
_Avoid_: cron, job, таймер, режим доставки

**Report (отчёт)**:
Плановая сводка по расписанию: ночные отчёты памяти, утренний дайджест.
Выключается тумблером в `/menu` → Уведомления и по умолчанию выключен.
_Avoid_: digest как общее слово (дайджест — один конкретный Report)

**Alert (алерт)**:
Notice о проблеме или требуемом действии: алерты brain, предложение обновиться.
Не выключается, поэтому обязан говорить, что делать, и не повторяться чаще
раза в неделю на одну проблему (ADR-0007).
_Avoid_: offer/оффер как имя Notice, warning, ошибка (ошибка — исход операции)

### Безопасность

**Gate**:
Только про security: inbound-гейт (санитайзер входа) и outbound-гейт
(сканер всего, что уходит в чат: ответ модели через Outbox и служебные реплики
с runtime-контентом). Авторизация — это allowlist и bearer, не gate. Правила
фенсов в карточках — контракт write_card, не gate.
_Avoid_: gate для auth, CI и человеческих чекпойнтов

**Allowlist**:
`TELEGRAM_ALLOWED_USER_IDS` — перечень Telegram-пользователей, которым агент
отвечает. Пустой список = не отвечает никому.
_Avoid_: whitelist

**Channel**:
Транспортный адаптер eve (`agent/channels/`). Другие смыслы запрещены: ветка
обновления — Update branch, тип чата Telegram — называть явно.
_Avoid_: channel для веток, чатов и «каналов данных»

**Inbound pipeline (входной пайплайн)**:
Единственный вход внутрь (`agent/lib/telegram-inbound.ts`): из сырого апдейта
Telegram получается ход модели или ничего. Внутри — allowlist, решение о
диспатче, запись в Vault, медиа, inbound-Gate и сборка контекста хода. Зеркало
Outbox: наружу — Outbox, внутрь — inbound pipeline.
_Avoid_: парсер апдейтов, обработчик входящих

**Outbox**:
Единственный шов наружу (`agent/lib/outbox.ts`): через него проходит всё, что
агент говорит в Telegram, и внутри него живёт outbound-гейт. Служебные реплики
самого канала (статус, ack) — не Outbox, но гейт они проходят там же.
_Avoid_: outbox для очереди сообщений и папки «исходящие»
