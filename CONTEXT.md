# Iva

Глоссарий проекта. Одно понятие — одно слово. Слова из колонки _Avoid_ не
использовать ни в коде, ни в доках, ни в обсуждениях. Решения записаны в
`docs/adr/`, метод — в `docs/philosophy.md`.

## Language

### Память

**Vault**:
Личное хранилище памяти пользователя — markdown-файлы в отдельном приватном
git-репозитории.
_Avoid_: база, хранилище памяти, knowledge base

**Card (карточка)**:
Типизированная единица памяти в `vault/cards/` с frontmatter по `schema.json`.
_Avoid_: заметка, запись, документ

**Compiled Truth**:
Актуальное значение карточки: frontmatter плюс верхнее описание. То, что
считается правдой сейчас, в отличие от истории изменений.
_Avoid_: current value, действующая правда

**History**:
Append-only секция `## History` Card или файл `CORE.history.md`. Пишется только кодом; модель не может
вложить в неё выдуманный архив. Строка Compiled Truth, которую заменила новая,
уходит сюда с датой; строку, написанную человеком, ночь не меняет, а дописывает
новое рядом.
_Avoid_: резервная копия

**Log**:
Append-only секция `## Log` Card: датированные факты с указателем на сырой день. Log не заменяет Compiled Truth.
_Avoid_: History, журнал процесса

**CORE**:
Always-on память: `vault/CORE.md`, не длиннее 3600 знаков, инжектится в каждый
ход.
_Avoid_: системный промпт (это не он), ядро

**PERSONA**:
Стиль общения агента: `vault/PERSONA.md`, не длиннее 800 знаков, инжектится в
каждый ход.
_Avoid_: характер, персонаж

**MOC**:
Замороженный ручной индекс тем vault (`vault/MOC.md`). Ночь его не ведёт и не пересобирает.
_Avoid_: оглавление, каталог, регенерация индекса

**Rollup**:
Ночная сборка памяти: сырой день превращается в Card и выжимки по цепочке
daily → weekly → monthly → yearly. Круг ведёт код: четыре Step; вызовов модели на Step столько, сколько нужно для частей, пачек и периодов.
Каждый вызов даёт один структурный ответ; файлы пишет код (ADR-0016).
_Avoid_: consolidation, консолидация, DAG, диаризация, свободный цикл
(диаризация — название способности модели в philosophy.md, не процесса)

**Step (шаг ночи)**:
Один из четырёх этапов Rollup: день → Card → связи → CORE. Вход собирает код. Один вызов обрабатывает одну часть входа и даёт один ответ.
Открытого цикла инструментов и дополнительного запроса Card нет. Step — ещё и шаг мастера
(`WizardStep` в `scripts/lib/tg-flow.ts`), и это тоже не Phase.
_Avoid_: turn для шага (Turn — ход), итерация, шаг агента

**Ceiling (предел)**:
Верхняя граница расхода. У фонового хода — 40 шагов, у Brief — 60, у Helper — 80;
суммарные входные токены — 4 млн на ход. На последнем шаге инструменты снимаются,
ход подводит итог; пустой итог сообщает, на скольких шагах остановилась Ива.
Токены проверяются между вызовами: пересекающий предел вызов и итог могут выйти за 4 млн.
У ночи — на один ход: шаги модели и входные токены;
достигнут — ход отменяется вместе с задачами, день получает попытку, догон
продолжается следующим днём, ночь кончается кодом 1 и называет обрез. У Watch, Brief и
Insight — на день владельца (`proactive.ceilingTokensPerDay`, токены их ходов; 0 —
выключен): достигнут — Insight и Brief в этот день не идут, Watch сообщает только сбои.
_Avoid_: бюджет, лимит (лимит — у провайдера), quota, потолок

**Attempt (попытка дня)**:
Один запуск Rollup над одним днём, закончившийся наблюдённым отказом самого дня:
обрез пределом, ход без отчёта, незакрытый день. После трёх день ждёт человека
(`iva jobs skip`), а не новой попытки на каждом старте; успех дня их стирает.
_Avoid_: retry, ретрай, повтор

**Trial run (пробный прогон)**:
Rollup над настоящими днями с записью в копию vault; настоящий vault ведёт
действующая ночь. Так новая ночь сравнивается со старой до включения.
_Avoid_: shadow mode, тень, dry-run (dry-run — печать плана у команды)

**Forget (забыть)**:
Удаление по явной команде владельца всех следов сущности или темы: карточки,
строки CORE, упоминания в днях и саммари, история git. Сначала перечень, потом
«да» владельца, потом удаление.
_Avoid_: очистка, purge, стирание, decay

**Month (месяц памяти)**:
Календарный месяц, с 1-го по последнее число; monthly-саммари берёт недели по
краям частями. Неделя остаётся как есть.
_Avoid_: четыре недели, 28 дней

**Brain**:
Детерминированный ночной уход за vault: бэкап, граф ссылок и Alert. Без модели и Python (ADR-0016).
_Avoid_: memory doctor, доктор памяти, autograph (как имя процесса Ивы)

### Процессы

**Harness**:
Тонкая программа-обвязка вокруг модели: eve плюс минимальный слой интеграции.
Определение и границы — в `docs/philosophy.md`.
_Avoid_: фреймворк, платформа

**Bridge (мост)**:
Отдельный процесс long-polling Telegram → localhost POST в eve. Живёт в
`scripts/poller/`, работает даже когда агент занят или завис.
_Avoid_: poller, поллер, transport

**Turn (ход)**:
Одна обработка входящего сообщения агентом, от приёма до ответа.
_Avoid_: run (это eve workflow run — внутренняя сущность), job (Job — запуск расписания, не ход)

**Chat record (запись чата)**:
Файл `data/run-status.d/<чат>.json` — одна машина состояний чата: занят (`accepted`, `turn`,
`compacting`), завис (`stale`) или свободен (`free`, `retiring`, `retry-offered`,
`awaiting-owner`). Пишут его три процесса под одним замком с CAS: агент, Bridge и ход
напоминания из своего процесса. Состояние выводит одна функция `chatState`, поля строки
держит `rowRules` (`agent/lib/run-status.ts`); модель — `specs/ChatRecord.tla`.
_Avoid_: статус чата, статус хода, run-status как имя состояния

**Phase (фаза)**:
Поле записи, которое называет состояние машины одним словом из перечисления: `phase`
напоминания (`waiting`, `running`, `delivered`, `failed`, `abandoned`), намерения сброса
(`none`, `blocked`, `recorded`, `waiting`, `escalated`), входа юзербота (`idle`, `starting`,
`waiting`, `password_needed`, `authorized`, `expired`, `error`, `interrupted`). Слово читают
`iva doctor`, инструменты модели и `iva jobs status`. Step — шаг ночи или шаг мастера, а не фаза.
_Avoid_: last_status (поле, которое `phase` заменило), «статус» для поля фазы

**Compaction (свёртка)**:
eve заменяет старую часть истории сессии пересказом; последние сообщения остаются дословно.
Между ходами её просит Ива после законченного хода, и чат на это время занят
(`agent/lib/idle-compaction.ts`); внутри хода eve делает её сама как страховку. Свёртка
живёт в сессии и к памяти (Vault, Rollup) отношения не имеет.
_Avoid_: саммаризация, сжатие контекста, очистка истории

**Job (запуск расписания)**:
Один запуск одного расписания; исход пишется в `data/jobs.json` по политике фактов
расписания: провал — всегда, успех — всегда или только закрывая прошлый провал
(`after-failure` у получасового proactive), а пропущенный политикой успех остаётся в
`data/rollup-status.json`.
НЕ ход агента (Turn) — ход, который будит запуск, остаётся Turn.
_Avoid_: job для хода агента, «джоба», запуск расписания как Turn

**Job reservation (бронь Job)**:
Запись брони запуска расписания рядом с фактами, в `data/rollup-status.json`: `inProgressSince`,
`ownerPid`, `ownerStartedAt`. Состояния `free`, `running`, `owner-dead`, `expired` выводит одна
функция `jobState` (`agent/lib/job-state.ts`) по записи и живучести процесса; `iva jobs status`
называет её словом. Бронь мёртвого процесса снимает заявка следующего запуска, в том числе
бронь прошлого процесса с тем же pid.
_Avoid_: lock расписания (замок — у файла), флаг inProgress

**Doctor**:
`iva doctor` — диагностика и починка инсталляции. Только про установку, не про
память.
_Avoid_: использовать слово для ухода за памятью (это Brain)

**Skill**:
Markdown-процедура агента (`agent/skills/` — ядровые, custom layer —
пользовательские). Кодирует «как делать», конкретику подставляет вызов.
Содержимое плагина или ядра, а не единица поставки.
_Avoid_: расширение

**Plugin (плагин)**:
Папка формата Agent Plugins: `plugin.json`, `skills/`, `mcp.json` и наш код под
`sh.iva/` (eve Extension, сервисы). Единица расширения Ивы. Ставится командой
`iva plugin add` из Marketplace, git-источника или локальной папки в
`data/custom/plugins/` (ADR-0008, ADR-0009). Плагин с `mcp.json` или `sh.iva/` модель
только предлагает (`iva plugin propose`), ставит его Bridge по тапу владельца.
_Avoid_: расширение (как термин), addon, модуль

**Marketplace (маркетплейс)**:
JSON-список плагинов в git-репо (`.agents/plugins/marketplace.json`, конвенция
Codex): имя → источник. У Ивы один по умолчанию, владелец добавляет свои. Не
реестр: без центра и модерации.
_Avoid_: реестр, registry, стор, каталог

**MCP proxy (прокси)**:
Сервис Ивы, который держит stdio MCP-сервер плагина и отдаёт его агенту по
streamable-http на loopback с bearer. Один сервис на один сервер.
_Avoid_: мост, bridge (это Telegram-поллер), gateway

**Plugin service (сервис плагина)**:
Долгоживущий процесс плагина, объявленный в `sh.iva/services/<svc>/service.json`:
Ива поднимает его юнитом `iva-plugin-<scope>-<name>-<svc>.service` (scope от canonical dataRoot; retained legacy — `iva-plugin-<name>-<svc>.service`) и сообщает выданный порт
через `IVA_SERVICE_PORT`. Своего протокола Ива ему не задаёт — этим он и отличается
от MCP proxy.
_Avoid_: демон, воркер, sidecar

**Plugin mode (режим плагина)**:
Пара тумблеров `enabled` × `trusted` в записи плагина, прочитанная одной функцией
`pluginMode` (`agent/lib/plugin-store.ts`): `full` (включён и доверен), `no-processes`
(включён без доверия — MCP proxy и сервисы его не идут), `paused` (выключен, доверие помнится,
включается без нового вопроса о процессах) и `off`. По режиму решает план юнитов
(`pluginUnitPlan`), откат сборки возвращает только свои тумблеры, а обновление после сверки
останавливает юниты того, что перестало быть `full`.
_Avoid_: состояние плагина, статус плагина, флаг паузы

**Trace (трейс)**:
Журнал событий хода в `data/trace/`: eve-события через хук плюс швы Ивы
(Bridge, Inbound pipeline, Gate, Outbox). Пишет ядро; читают вьюер плагина
`trace` и `iva trace`. Один ход = цепочка событий с общим `turn`.
_Avoid_: лог (это журнал сервиса), телеметрия, OTel-трасса (внутренность eve)

**Userbot login (вход юзербота)**:
Вход в аккаунт владельца в отдельном сервисе `services/telegram-userbot/`: один аккаунт, один
процесс и одна фаза `phase` (`idle`, `starting`, `waiting`, `password_needed`, `authorized`,
`expired`, `error`, `interrupted`) рядом с файлом сессии. Файл-отметка
`telegram-userbot.login` лежит на диске, пока вход идёт, поэтому после перезапуска прокси знает,
что вход оборван (`interrupted`), а не начат с нуля. Фаза в памяти, ответ Telegram и фаза от
`Login.phase()` различаются; `/healthz` отдаёт фазу как `login`, `iva userbot status` и `iva doctor`
читают её по тому же списку. Модель — `specs/UserbotLogin.tla`.
_Avoid_: статус юзербота, состояние подключения, сессия как имя фазы

**Schedule**:
Внутрипроцессный cron eve (`agent/schedules/`). Диспетчер напоминаний — такой же
минутный Schedule. Внешний запуск по расписанию выполняет юнит-таймер systemd на Linux
или задание launchd с `StartCalendarInterval` на macOS. `systemd-run` — отдельный механизм.
_Avoid_: cron (без уточнения какой)

**Unit (юнит)**:
Юнит systemd на Linux или задание launchd на macOS. На macOS метка имеет вид
`app.iva.*`, плист лежит в `~/Library/LaunchAgents`.
_Avoid_: демон, служба как имя механизма в коде и документации; человеческие строки
«службы Ивы» и «войдите в систему» используют обычный язык.

### Доставка и установка

**Authored tree**:
Поставляемое ядро агента — дерево `agent/`, которое eve открывает по
file discovery. Обновляется релизами.
_Avoid_: core (перегружено), исходники агента

**Custom layer**:
Пользовательский оверлей `data/custom/agent/**`, переживающий обновления.
Сюда же ставятся плагины.
_Avoid_: authored layer, кастомизация (как термин)

**Owner rules (правила владельца)**:
Markdown-файлы `data/custom/agent/instructions/*.md`, которые читаются с диска каждый ход
рядом с встроенной персоной; в чате их пишет модель через `write_file` после подтверждения
владельца. Не CORE (там факты и цели), не PERSONA (там стиль из квиза), не код (сборка не
нужна).
_Avoid_: кастомная персона, замена инструкции, override

**Release (выпуск)**:
Опубликованная версия проекта: метка `vX.Y.Z` на `main` и запись в CHANGELOG. В `main`
живут только выпуски (ADR-0018). Обновление ни в одной ветке не
уводит установку назад (ADR-0018).
Только патч-инкременты; минор и мажор объявляет владелец.
_Avoid_: версия (без уточнения), стабильный канал

**Beta updates (бета-обновления)**:
Выбор владельца установки (`iva beta` / `iva stable`): Update branch `beta`, обновление
ставит её вершину, а не новейший Release. Решает только ветка; git-config `iva.beta`
бета-сборок до 0.5.0 не читается, выбор его снимает. `iva stable` возвращает Update branch
`main`. По умолчанию выключены (ADR-0018).
_Avoid_: бета-канал, канал обновления, update channel

**Version (каталог версии)**:
Неизменяемый каталог установки `~/iva/versions/<ver>-<sha12>/` в апдейтере v2.
Активную версию выбирает симлинк `current`; откат — переброс симлинка.
_Avoid_: билд, инсталляция

**Update branch**:
Git-ветка, с которой `iva update` берёт код (git-config `iva.updateBranch`): `main` —
выпуски, `beta` — бета-обновления (ADR-0018), `release/<v>` — после `iva rollback`.
_Avoid_: канал обновления, update channel (channel зарезервирован за eve)

**Update floor (нижняя граница обновления)**:
Самый старый Release, с которого обновление ставит дерево (`minUpdater` в `update-compat.json`).
Установка ниже границы получает отказ до первого переключения, продолжает работать на своей
версии и уходит в ремонт через Step release. Границу проверяют оба половины обновлятора: кандидат
до `npm ci` и сам ход обновления (`specs/UpdateFloor.tla`).
_Avoid_: минимальная версия, min version

**Step release (ступенька)**:
Последний Release, чей обновлятор принимает любую установку ниже Update floor. Его ветка
`release/<v>` существует только для ремонта: `repair.sh` закрепляет на неё Update branch и
переводит установку сначала на неё, потом на новейший Release. Формы, которые ступенька читает
лениво, она же переводит своим кодом до второго обновления.
_Avoid_: промежуточная версия, bridge release

**Update run journal (журнал хода обновления)**:
Файл `data/update-run.json`, который ход обновления пишет до первой остановки служб: шаг,
снимок юнитов, куда ушли сессии, чем кончилось. Его читают повтор после обрыва, Bridge и
`iva doctor`; следующее обновление перезаписывает его на старте. Версии ниже 0.5.12 файла не
знают и откат его не замечает (`specs/UpdateRun.tla`).
_Avoid_: лог обновления (лог — у службы), update status-файл

**Button (кнопка)**:
Элемент rich message (`<tg-button>`), стоящий в строке текста рядом с пояснением, что он
делает; несёт `callback_data`. Единственный способ дать пользователю выбор тапом: Bridge
рисует их для экранов меню и мастеров, модель — в ответе по скиллу `rich-replies`.
Тап по кнопке модели Bridge превращает в обычное сообщение пользователя с текстом из
`callback_data` и следом текстом сообщения, под которым стояла кнопка (до 1500 знаков). Нажатую кнопку Bridge сразу помечает «✅» и красит в зелёный, а повторный
тап по ней не становится вторым сообщением; остальные кнопки сообщения остаются. (ADR-0015)
Исключение — «Я в курсе» под пунктом Watch: Bridge сам удаляет сообщение, ход модели не идёт.
_Avoid_: inline-клавиатура, reply_markup, клавиатура

**Widget (виджет)**:
Живая карточка Telegram (Bot API 10.4, `sendWidget`): HTML с CSS и JS, который клиент рисует
в пузыре сообщения, без сети, в песочнице Telegram. Модель пишет её в ответе блоком
` ```tg-widget <подпись> ` по скиллу `widgets`; Outbox шлёт его отдельным сообщением, а при
отказе — подпись текстом. Подпись — ответ словами для приложений без виджетов. Тапы
действуют только внутри карточки; просьба к Иве — кнопкой в тексте после неё.
_Avoid_: мини-апп, web app, HTML-сообщение

**Screen (экран)**:
Одно сообщение меню или мастера, которое Bridge правит на месте: markdown с заголовком,
пояснениями и кнопками. Экран возвращает одну строку текста, а не «текст + ряды».
_Avoid_: клавиатура, форма, страница

### Уведомления

**Notice (уведомление)**:
Всё, что Iva шлёт сама, без хода пользователя. Видов пять: Report, Alert, Watch, Brief, Insight.
_Avoid_: notification, пуш, рассылка

**Watch (присмотр)**:
Notice о пропущенном: код раз в час проверяет источники (Telegram, почта) без модели,
модель будится только при новом и решает, писать ли (ADR-0020).
_Avoid_: heartbeat, пульс, мониторинг, polling

**Brief (обзор)**:
Notice по расписанию два раза в день: модель обходит подключения владельца, цели, погоду.
Заменяет утренний дайджест (ADR-0020).
_Avoid_: digest, дайджест, сводка, briefing

**Insight (инсайт)**:
Notice раз в день в заданное владельцем время (`proactive.insightTimes`, по умолчанию выключен, не в
тихие часы): модель сама ищет одно дело, которое владелец делает руками, собирает под него черновик
плагина, прогоняет и предлагает кнопками «Поставить» / «Не надо» — или молчит. Сбой в коде Version из
списка сбоев за сутки она может вместо черновика предложить разработчику кнопками «Разработчику» /
«Не надо»; ссылку на issue даёт ход после тапа. Ставит только ход после тапа. Не больше одного в
день; «Не надо» снимает только этот плагин, паузы у Insight нет (ADR-0022).
_Avoid_: idea (занято типом Card), инициатива (ось квиза PERSONA), offer/оффер, совет дня, рекомендация, spark, находка

**Signal (сигнал)**:
Сообщение, которое плагин или скрипт на той же машине передаёт Иве командой `iva signal`;
становится разовым Reminder.
_Avoid_: event (занято eve), webhook, trigger, MCP Events

**Reminder (напоминание)**:
Разовое дело в срок: просьба пользователя, Signal плагина (`iva signal`) или обещание, которое Ива
дала в чате и поставила себе сама. Живёт строкой в таблице напоминаний `data/`; минутный
Schedule-диспетчер забирает созревшие строки одним атомарным переходом `pending → fired`, а ребёнок в
срок делает одно дело: текст строки идёт промптом в свежую сессию, агент выполняет его инструментами, и
код отправляет финальный текст хода в чат и тему, где напоминание поставили. Хода не было или он
промолчал - код шлёт текст строки как есть. Не Report и не Alert: это исполнение просьбы или данного
в разговоре обещания, и тумблеры Notice его не выключают.
_Avoid_: notification, напоминалка, alarm, режим доставки

**Routine (рутина)**:
Повторяющееся напоминание: строка той же таблицы в `data/` с расписанием и зоной владельца,
которую диспетчер забирает по сроку на каждом срабатывании. Факт последнего срабатывания
(`firedAt`, `delivered`, `error`) лежит в той же строке, в срок происходит то же самое, что
у разового. Ставится тем же тулом `remind` с `action: "add"`.
_Avoid_: cron, job, таймер, режим доставки

**Firing (срабатывание)**:
Одно срабатывание строки Reminder или Routine: `firedAt` плюс то, чем оно кончилось. Исход
называет `phase` (`waiting`, `running`, `delivered`, `failed`, `abandoned`); каждая попытка
доставки — один `capture`, `firedAt` — тот ключ, с которым `recordDelivery` сравнивает запись перед
каждой записью. Модель — `specs/ReminderLifecycle.tla`.
_Avoid_: tick, запуск напоминания, firing как имя хода

**Abandoned firing (брошенное срабатывание)**:
Срабатывание, у которого ни факта, ни причины: Ива перезапустилась или упала между стартом
ребёнка и записью исхода, а живой ребёнок этого процесса его не держит. Закрывается
причиной один раз (`phase`: `abandoned`), текст заново не уходит: таблица не знает, ушёл ли он.
Владельцу идёт один Alert на срабатывание; строка с таким срабатыванием видна в `iva doctor`,
а взятие на следующий срок и уборка ждут этого Alert.
_Avoid_: потерянное напоминание, мёртвое срабатывание

**Report (отчёт)**:
Плановая сводка по расписанию — только ночные отчёты памяти.
Выключается тумблером в `/menu` → Уведомления и по умолчанию выключен.
_Avoid_: digest (утренний обзор — Brief)

**Alert (алерт)**:
Notice о проблеме или требуемом действии: алерты brain, предложение обновиться, сбой
регулярной задачи, заводская сборка версии (ваши файлы в data/custom не собрались), юзербот
выключен после обновления.
Не выключается, поэтому обязан говорить, что делать, и не повторяться чаще
раза в неделю на одну проблему (ADR-0007).
_Avoid_: offer/оффер как имя Notice, warning, ошибка (ошибка — исход операции)

### Безопасность

**Gate**:
Только про security: inbound-гейт (санитайзер входа) и outbound-гейт
(сканер всего, что уходит в чат: ответ модели через Outbox и служебные реплики
с runtime-контентом). Авторизация — это allowlist и bearer, не gate. Правила
фенсов в карточках — контракт write_card, не gate.
_Avoid_: gate для auth, CI и человеческих чекпойнтов

**Allowlist**:
`TELEGRAM_ALLOWED_USER_IDS` — перечень Telegram-пользователей, которым агент
отвечает. Пустой список = не отвечает никому.
_Avoid_: whitelist

**Channel**:
Транспортный адаптер eve (`agent/channels/`). Другие смыслы запрещены: ветка
обновления — Update branch, тип чата Telegram — называть явно.
_Avoid_: channel для веток, чатов и «каналов данных»

**Inbound pipeline (входной пайплайн)**:
Единственный вход внутрь (`agent/lib/telegram-inbound.ts`): из сырого апдейта
Telegram получается ход модели или ничего. Внутри — allowlist, решение о
диспатче, запись в Vault, медиа, inbound-Gate и сборка контекста хода. Зеркало
Outbox: наружу — Outbox, внутрь — inbound pipeline.
_Avoid_: парсер апдейтов, обработчик входящих

**Outbox**:
Единственный шов наружу (`agent/lib/outbox.ts`): через него проходит всё, что
агент говорит в Telegram, и внутри него живёт outbound-гейт. Служебные реплики
самого канала (статус, ack) — не Outbox, но гейт они проходят там же.
_Avoid_: outbox для очереди сообщений и папки «исходящие»

**Helper (помощник)**:
Фоновый ход Ивы с отдельной чистой историей и полным набором её инструментов; Ива задаёт задание и границы действий владельца.
_Avoid_: subagent для помощника, worker, фоновая задача

**Outcome (исход)**:
Результат работы помощника, который Ива читает через `helper outcome` и пересказывает владельцу в основном чате; частичный итог содержит последнее завершённое сообщение.
_Avoid_: Report для исхода, отчёт помощника

**Goal**:
То, что Ива доводит до результата через проверки помощника; закрывает владелец.
В английских инструкциях цели CORE называются CORE goals, этот механизм — goal.
_Avoid_: цель (цели CORE), поручение, errand, задача, миссия

**Goal check (проверка goal)**:
Строка помощника, которая ведёт goal и записывает Verdict.
_Avoid_: отчёт проверки, report

**Verdict (вердикт)**:
Итог проверки для goal: quiet, news, done или blocked, с планом и сроком следующей проверки.
_Avoid_: report, отчёт проверки
